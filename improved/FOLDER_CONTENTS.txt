EVALUATION SCRIPTS (5 files)
================================================================================

1. llm_judge_evaluator.py (16KB)
   - LLM-as-a-Judge evaluation using GPT-5.2
   - Checks: constraints, optimality, text accuracy, formatting
   - Stricter evaluation (catches suboptimal solutions)

2. evaluate_structured_outputs.py (11KB)
   - Constraint-based evaluation (programmatic)
   - Checks: time windows, travel times, meeting durations
   - More lenient (only checks feasibility)

3. convert_to_structured_output.py (11KB)

4. extract_meeting_constraints.py (6KB)

5. compare_all_evaluations.py (6KB)

   - Compares LLM judge vs constraint-based accuracy

KEY FINDINGS (from experiments)
================================================================================

✅ Python prompting >> SMT prompting for all models
   - GPT-5: 95% (Python) vs 10% (SMT) = +85% improvement
   - Best SMT: 11% vs Worst Python: 5%

✅ Top 3 Models (Constraint-Based):
   1. Deepseek-Reasoner-Python: 97%
   2. GPT-5-Python: 95%
   3. O3-mini-Python: 82%

✅ Evaluation Insights:
   - LLM judge is stricter (catches optimality issues)
   - Constraint-based is more reliable (no hallucinations)
   - ~10-30% gap between evaluators for most models

✅ Recommendations:
   - Use Python prompting for meeting planning tasks
   - Use constraint-based evaluation for feasibility
   - Use LLM judge for optimality checking
   - Investigate disagreements manually
