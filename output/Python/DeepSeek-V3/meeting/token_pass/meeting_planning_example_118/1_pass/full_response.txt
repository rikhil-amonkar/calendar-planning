Let’s break this down step by step before writing the code.

**Step 1 – Understanding the problem**  
We start at **Bayview at 9:00 AM**.  
We have two friends:  
- **Richard** at Union Square from 8:45 to 13:00 (1:00 PM), need at least 120 minutes with him.  
- **Charles** at Presidio from 9:45 to 13:00, need at least 120 minutes with him.  

Travel times are asymmetric:  
- Bayview → Union Square: 17 min  
- Bayview → Presidio: 31 min  
- Union Square → Bayview: 15 min  
- Union Square → Presidio: 24 min  
- Presidio → Bayview: 31 min  
- Presidio → Union Square: 22 min  

We want to meet **as many friends as possible** — here that means both, if possible, given time constraints.

**Step 2 – Feasibility check**  
If we meet both, we have to travel between them, and each meeting must be ≥ 120 minutes.  
Let’s try meeting Richard first, then Charles.

**Option A: Richard first, then Charles**  
Start at Bayview 9:00 → travel 17 min → arrive Union Square 9:17.  
Richard is available from 8:45, so we can start at 9:17.  
We need 120 min with Richard → end at 11:17.  
Then travel Union Square → Presidio: 24 min → arrive Presidio 11:41.  
Charles is available from 9:45 to 13:00.  
We can meet Charles from 11:41 to 13:00 → that’s 79 minutes, not enough (need 120).  
So this fails.

**Option B: Charles first, then Richard**  
Start at Bayview 9:00 → travel 31 min → arrive Presidio 9:31.  
Charles available from 9:45, so earliest start with Charles is 9:45.  
Meet Charles 120 min → end at 11:45.  
Travel Presidio → Union Square: 22 min → arrive Union Square 12:07.  
Richard available until 13:00.  
Meet Richard from 12:07 to 13:00 → 53 minutes, not enough.  
So fails.

**Step 3 – Can we meet only one?**  
Yes, but we want as many as possible — but both seems impossible given travel + 120 min each.  
Let’s check if we can meet both with shorter meetings? No, constraint says minimum 120 each, so can’t shorten.

**Step 4 – Check if overlapping stays allow meeting both with travel in middle**  
We have from 9:00 to 13:00 total = 4 hours = 240 minutes.  
If we meet both for 120 each, that’s 240 minutes of meeting, no travel time possible.  
But we must travel between them, so impossible to meet both for full 120 each.

Thus, maximum friends = 1.

**Step 5 – Which one gives more feasible time?**  
We can meet either Richard or Charles for 120 minutes easily.

- Meet Richard:  
Start Bayview 9:00 → arrive Union Square 9:17 → meet until 11:17 (exactly 120 min).  
That works.

- Meet Charles:  
Start Bayview 9:00 → arrive Presidio 9:31 → wait until 9:45 → meet until 11:45 (120 min).  
That also works.

Both single meetings are possible. Which is better?  
Maybe we can meet one and then meet the other for leftover time? Let’s check:

If we meet Richard 9:17–11:17, then travel to Presidio (24 min) → arrive 11:41, meet Charles until 13:00 → 79 min (not enough for min 120).  
If we meet Charles 9:45–11:45, then travel to Union Square (22 min) → arrive 12:07, meet Richard until 13:00 → 53 min (not enough).

So indeed only one full meeting possible.

**Step 6 – Choose the one that allows more total time with friends?**  
We can’t meet both, so pick one.

Richard available 8:45–13:00 (4h15min).  
We arrive 9:17, could stay until 13:00 → 3h43min with Richard.

We arrive 9:31, wait until 9:45, could stay until 13:00 → 3h15min with Charles.  

So Richard gives slightly more total time (3h43 vs 3h15).  
But the problem says “like to meet for a minimum of 120 minutes” — that’s a requirement, not a “must maximize beyond 120”.  
Since both satisfy minimum, maybe we just pick one.  
But the goal is “meet as many friends as possible” — number of friends is same (1) either way.  
So either is valid.

I’ll pick Richard because less initial travel time (17 vs 31 min), so more free time after meeting?  
But after meeting Richard, day ends at 13:00 anyway.  
Actually, after meeting Richard from 9:17 to 13:00, that’s the whole available time.  
After meeting Charles from 9:45 to 13:00, also whole available time.  
So no difference.

**Step 7 – Write program to compute this**  
We’ll encode constraints, try both permutations of visits, see if both meetings possible.  
If not, pick one meeting that satisfies.

```python
import json
from datetime import datetime, timedelta

def time_to_str(t):
    return f"{t.hour}:{t.minute:02d}"

def str_to_time(s):
    return datetime.strptime(s, "%H:%M")

def compute_schedule():
    # Travel times in minutes
    travel = {
        ("Bayview", "Union Square"): 17,
        ("Bayview", "Presidio"): 31,
        ("Union Square", "Bayview"): 15,
        ("Union Square", "Presidio"): 24,
        ("Presidio", "Bayview"): 31,
        ("Presidio", "Union Square"): 22,
    }
    
    # Constraints
    start_location = "Bayview"
    start_time = str_to_time("9:00")
    
    friends = [
        {
            "name": "Richard",
            "location": "Union Square",
            "available_start": str_to_time("8:45"),
            "available_end": str_to_time("13:00"),
            "min_duration": 120,
        },
        {
            "name": "Charles",
            "location": "Presidio",
            "available_start": str_to_time("9:45"),
            "available_end": str_to_time("13:00"),
            "min_duration": 120,
        }
    ]
    
    # Try both orders
    best_itinerary = []
    max_meetings = 0
    
    from itertools import permutations
    for perm in permutations(friends):
        current_time = start_time
        current_loc = start_location
        itinerary = []
        meetings_count = 0
        
        for friend in perm:
            # Travel to friend's location
            travel_key = (current_loc, friend["location"])
            travel_duration = travel[travel_key]
            arrive_time = current_time + timedelta(minutes=travel_duration)
            
            # Start meeting at earliest possible time after arrival
            meet_start = max(arrive_time, friend["available_start"])
            # End meeting at minimum duration
            meet_end = meet_start + timedelta(minutes=friend["min_duration"])
            
            # Check if meeting fits in availability
            if meet_end <= friend["available_end"]:
                meetings_count += 1
                itinerary.append({
                    "action": "meet",
                    "location": friend["location"],
                    "person": friend["name"],
                    "start_time": time_to_str(meet_start),
                    "end_time": time_to_str(meet_end),
                })
                current_time = meet_end
                current_loc = friend["location"]
            else:
                # This meeting not possible in this order
                break
        
        if meetings_count > max_meetings:
            max_meetings = meetings_count
            best_itinerary = itinerary
    
    # If no order allows both, just pick one friend (first in list)
    if max_meetings == 0:
        friend = friends[0]
        travel_key = (start_location, friend["location"])
        travel_duration = travel[travel_key]
        arrive_time = start_time + timedelta(minutes=travel_duration)
        meet_start = max(arrive_time, friend["available_start"])
        meet_end = meet_start + timedelta(minutes=friend["min_duration"])
        if meet_end > friend["available_end"]:
            # Adjust to fit within available time
            meet_end = friend["available_end"]
            meet_start = meet_end - timedelta(minutes=friend["min_duration"])
            if meet_start < friend["available_start"]:
                meet_start = friend["available_start"]
        best_itinerary = [{
            "action": "meet",
            "location": friend["location"],
            "person": friend["name"],
            "start_time": time_to_str(meet_start),
            "end_time": time_to_str(meet_end),
        }]
    
    return {"itinerary": best_itinerary}

if __name__ == "__main__":
    result = compute_schedule()
    print(json.dumps(result, indent=2))
```

**Explanation of the program:**
1. It encodes travel times and friend constraints.
2. It tries both permutations of visiting friends to see if both can be met.
3. If both can’t be met, it defaults to meeting one friend (Richard first, as per the list order).
4. It outputs the itinerary in the required JSON format.

When run, it will output the optimal schedule given the constraints.
