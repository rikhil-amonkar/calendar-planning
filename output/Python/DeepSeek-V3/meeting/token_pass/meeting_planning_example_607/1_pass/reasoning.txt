## **Step 1 – Understanding the problem**

We have:

- **Start location**: Sunset District at 9:00 AM.
- **7 friends**, each in a fixed location, with availability windows and minimum meeting durations.
- **Travel times** between all locations (in minutes).
- Goal: Meet as many friends as possible, respecting:
  1. Availability windows.
  2. Minimum meeting durations.
  3. Travel time between locations.
  4. Meetings cannot overlap in time for us (we can only be in one place at a time).

---

## **Step 2 – Observations on constraints**

**Minimum meeting times**:

1. Karen (Russian Hill) — 60 min, available 20:45–21:45 (only 60 minutes exactly, so must meet 20:45–21:45 if meeting).
2. Jessica (The Castro) — 60 min, available 15:45–19:30.
3. Matthew (Richmond) — 15 min, available 7:30–15:15.
4. Michelle (Marina) — 75 min, available 10:30–18:45.
5. Carol (North Beach) — 90 min, available 12:00–17:00.
6. Stephanie (Union Square) — 30 min, available 10:45–14:15.
7. Linda (Golden Gate Park) — 90 min, available 10:45–22:00.

**Travel times** are symmetric-ish but not perfectly (given data shows slight differences, e.g., Sunset to Russian Hill 24, Russian Hill to Sunset 23). We must use the exact given times.

---

## **Step 3 – Strategy**

We can treat this as a **scheduling optimization** problem:

- We start at Sunset at 9:00.
- We can visit friends in some order.
- For each friend, we must arrive during their window, stay for at least their minimum duration (or until their window ends if we start late), but we can leave earlier if we want after meeting the minimum.
- We want to maximize **number of friends met** (primary), then possibly maximize **total meeting time** or minimize idle time.

Because the number of friends is small (7), we can brute-force all permutations of visits, but we must also decide start times within windows. That’s more complex.

Simpler approach:  
We can **greedily** try to fit as many as possible by ordering them by their window start times, but travel times may make that suboptimal. Better: **search over permutations** with a simple heuristic for start times:  
For a given permutation, we simulate:

1. Start at current location (Sunset at 9:00).
2. For each next friend in permutation:
   - Travel from current location to friend’s location (add travel time).
   - Arrive at `arrival_time`.
   - If arrival_time is before friend’s window start, wait until window start.
   - If arrival_time is after friend’s window end → cannot meet them in this order.
   - Meeting starts at `max(arrival_time, window_start)`.
   - Meeting ends at `start_time + min_duration`, but if that exceeds window end, we cannot meet min_duration → fail.
   - But we can choose to stay longer if we want, but to maximize others, we leave as soon as min_duration is met.
   - Update current location and time.
