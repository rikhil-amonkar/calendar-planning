 Approach:

 We are scheduling on Monday only.

 Let's represent time in minutes from 9:00 (so 9:00 = 0, 10:00 = 60, 11:00 = 120, 17:00 = 8*60 = 480).

 Meeting duration: 30 minutes.

 We define a variable for the start time (in minutes from 9:00) of the meeting, say `start`.

 Constraints:

 1. start >= 0
 2. start + 30 <= 480 (because 17:00 is 480 minutes from 9:00)

 3. The meeting must not overlap with any of Albert's blocked times.

 Albert's blocked times in minutes from 9:00:
   Block1: 0 to 60 (9:00 to 10:00)
   Block2: 90 to 180 (10:30 to 12:00 -> 10:30 is 90 minutes from 9:00, 12:00 is 180 minutes from 9:00)
   Block3: 360 to 450 (15:00 to 16:30 -> 15:00 is 6*60=360, 16:30 is 7*60+30=450)

 4. Additionally, Albert cannot meet after 11:00. Since 11:00 is 120 minutes from 9:00, this means the meeting must end by 120 (11:00). So:
    start + 30 <= 120

 Now, we must ensure the meeting does not overlap with any blocked time. We can model that by:

 For each blocked interval [b_start, b_end]:
    (start + 30 <= b_start) OR (start >= b_end)

 But note: the blocked intervals are:
   Block1: [0, 60]
   Block2: [90, 180]
   Block3: [360, 450]

 However, note that the constraint that the meeting must end by 11:00 (120 minutes) already excludes block3 and part of block2.

 So we only need to avoid block1 and the part of block2 that is before 120? Actually, the meeting must end by 120, so we are only considering meetings that end at or before 120. Therefore, we only have to worry about block1 and the part of block2 that starts at 90 (which is before 120). 

 But note: the meeting must not overlap with block2 even if it ends at 120, because block2 starts at 90 and goes until 180. So if the meeting starts at 60 (10:00) and ends at 90 (10:30), then it does not overlap with block2 (which starts at 90). 

 So the constraints for the blocked times in the relevant range [0,120] are:

 For block1: [0,60]: we require the meeting to be after 60 (so start>=60) or before 0 (impossible). So we require start>=60.

 For block2: [90,180]: we require the meeting to end by 90 (so start+30<=90) or start>=180 (which is beyond our end time of 120). So we require start+30<=90.

 But note: the meeting must also satisfy the constraint of ending by 120 (which is already given).

 So we have:
   start >= 60
   start + 30 <= 90   => start <= 60

 Therefore, start must be exactly 60.

 So the meeting starts at 60 minutes from 9:00, which is 10:00, and ends at 90 minutes from 9:00, which is 10:30.
