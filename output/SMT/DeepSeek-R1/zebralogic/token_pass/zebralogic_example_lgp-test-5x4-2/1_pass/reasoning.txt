We are going to use the Z3 SMT solver to solve this puzzle.
 We have 5 houses. For each house, we have a name, color, phone model, and occupation.
 We'll define Z3 variables for each attribute per house.

 Steps:
 1. Define the house indices (1 to 5).
 2. Define the domains for each attribute (names, colors, phone models, occupations).
 3. Create Z3 variables for each attribute in each house.
 4. Add constraints that all attributes are distinct (each value appears exactly once).
 5. Add the constraints from the clues.

 Clues:
  1. The person who is an engineer is somewhere to the right of the person who is a lawyer.
  2. Bob is in the second house.
  3. The person who uses a Samsung Galaxy S21 is the person who is a doctor.
  4. The person who is a doctor is the person who loves blue.
  5. The person whose favorite color is green is not in the fifth house.
  6. The person who is a lawyer is the person who uses a OnePlus 9.
  7. The person who loves blue is directly left of the person whose favorite color is red.
  8. The person who is a lawyer is somewhere to the right of the person who uses a Samsung Galaxy S21.
  9. There is one house between the person who uses a Google Pixel 6 and the person who uses a Huawei P50.
  10. Arnold is the person who is an engineer.
  11. Alice is the person who loves yellow.
  12. The person who uses a Google Pixel 6 is Eric.
  13. The person who uses a Google Pixel 6 is the person who is a teacher.
  14. The person whose favorite color is red is somewhere to the right of the person who is a teacher.

 Note: We have to be cautious about the ordering of houses (left to right, 1 is leftmost, 5 is rightmost).

 Implementation:
 We'll create lists for each attribute (name, color, phone, occupation) for the 5 houses.

 We'll use Z3's IntSort and define a function to get the index of a value in a domain.

 Alternatively, we can use EnumSort for each attribute to make it more symbolic, but using integers and distinct constraints is also common.

 Let's define:
   names: Bob, Eric, Arnold, Alice, Peter -> we'll map to 0,1,2,3,4
   colors: blue, green, white, yellow, red -> 0,1,2,3,4
   phones: huawei p50, samsung galaxy s21, oneplus 9, iphone 13, google pixel 6 -> 0,1,2,3,4
   occupations: artist, teacher, doctor, engineer, lawyer -> 0,1,2,3,4

 But note: We have to output the string names, so we'll keep mapping arrays.

 Alternatively, we can use Z3's EnumSort for each category to avoid integer mapping and have more readable constraints.

 However, for simplicity and to avoid having to map back from Z3 symbols to strings, we can use integers and then map with arrays.

 Let's do:

   name_domain = ['Bob', 'Eric', 'Arnold', 'Alice', 'Peter']
   color_domain = ['blue', 'green', 'white', 'yellow', 'red']
   phone_domain = ['huawei p50', 'samsung galaxy s21', 'oneplus 9', 'iphone 13', 'google pixel 6']
   occupation_domain = ['artist', 'teacher', 'doctor', 'engineer', 'lawyer']

 For each house i (0 to 4, representing house 1 to 5), we define:
   name[i] = Int('name_i')
   color[i] = Int('color_i')
   phone[i] = Int('phone_i')
   occupation[i] = Int('occupation_i')

 Then we constrain each of these arrays to have distinct values in [0,4] (or [0, len(domain)-1])

 Then we add the constraints from the clues.

 However, note: The clues sometimes relate attributes of the same person (e.g., clue 3: the person with phone samsung is doctor) and sometimes relative positions.

 We'll also define helper functions to get the house index of a person with a given attribute? But note: we are using Z3, so we cannot use Python conditionals arbitrarily.

 Alternatively, we can use the following for relative positions:

 For clue 1: engineer is to the right of lawyer -> exists i, j such that occupation[i] = lawyer and occupation[j] = engineer and j > i.

 But we can also express without exists by using the house indices of the lawyer and engineer.

 We can define a function that returns the house index (0-4) for a given attribute value in a category. However, Z3 does not support returning an integer index directly for a condition.

 Instead, we can use:

   For any attribute, we can say: the house index where occupation is lawyer is less than the house index where occupation is engineer.

 How to get the house index for a given attribute value? We can use a Z3 function that maps an attribute value to a house index, but note that each value is unique.

 We can do:

   lawyer_house = Int('lawyer_house')
   s.add(And([If(occupation[i] == lawyer_index, lawyer_house == i, True) for i in range(5)]))

 But this is cumbersome for each attribute. Alternatively, we can use the following:

   Let lawyer_index = occupation_domain.index('lawyer')
   Then the house index of the lawyer is the i such that occupation[i] == lawyer_index.

 We can define a function to get the house index for a given value in an array of Z3 variables:

   def get_house_index(arr, value):
       return [If(arr[i] == value, i, -1) for i in range(5)]

 But note: we cannot use list comprehensions that return a list of Z3 expressions and then use Or, because the value is unique. Instead, we can use:

   house_index = Int('house_index_for_attr')
   s.add(Or([And(arr[i] == value, house_index == i) for i in range(5)]))

 However, this becomes messy if we have to do it for every attribute.

 Alternatively, we can avoid extracting the house index and instead express constraints by comparing the attributes in different houses.

 For example, for clue 1: engineer is right of lawyer.

   We can say: There exists a house i for lawyer and a house j for engineer with j > i.

   But we can also say: For the house that has lawyer, there is a house to the right that has engineer.

   We can do:

      s.add(Or([And(occupation[i] == lawyer_index, Or([And(occupation[j] == engineer_index, j > i) for j in range(5)])) for i in range(5)]))

   But note: This is inefficient and creates many constraints. Alternatively, we can use:

      lawyer_pos = Int('lawyer_pos')
      engineer_pos = Int('engineer_pos')
      s.add(lawyer_pos >= 0, lawyer_pos < 5)
      s.add(engineer_pos >= 0, engineer_pos < 5)
      for i in range(5):
          s.add(If(occupation[i] == lawyer_index, lawyer_pos == i, True))
          s.add(If(occupation[i] == engineer_index, engineer_pos == i, True))
      s.add(engineer_pos > lawyer_pos)

   This is more efficient and readable.

 But note: We have multiple such constraints, so we might want to write a helper function.

 However, to keep the code simple and avoid too many auxiliary variables, we can also express without extracting positions for every attribute.

 Let's consider the clues:

  Clue 1: engineer is right of lawyer -> we can use the method with two auxiliary variables for lawyer and engineer positions.

  Clue 8: lawyer is right of the person with samsung galaxy s21 -> we'll need the position of the samsung user and the lawyer.

  Clue 9: one house between google pixel and huawei p50 -> |pos_google - pos_huawei| = 2.

  Clue 14: red color is right of the teacher -> we need the position of red and teacher.

 So we will need to extract house indices for several attributes.

 Let's define a function that, given an array of Z3 variables (for the 5 houses) and a value, returns the house index (0-4) for that value.

 However, note: We cannot return a Z3 expression from a function and then use it in multiple constraints without having to reevaluate the conditions.

 Alternatively, we can define a function that adds constraints to set an auxiliary variable to the house index of a given value.

 We'll do:

   def get_position(s, arr, value, pos_var):
       constraints = []
       for i in range(5):
           constraints.append(If(arr[i] == value, pos_var == i, True))
       s.add(constraints)

 But note: This function will add 5 constraints to the solver. We'll create an Int variable for each attribute we are interested in.
